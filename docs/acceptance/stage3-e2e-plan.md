# 段階3 E2Eシナリオと受入基準

## 1. 目的と範囲

追熟計画からエチレン注入、寝かせ、追熟確認、部分出荷、取消までを実運用順で確認し、
工程ボード、期限、在庫残量、ラベル、CSVが同じ状態を示すことを検証する。
LocalとStagingでは一意な実施識別子を付けたダミーデータだけを使用する。

自動テストは回帰検出、Staging・実機・現場操作は業務受入の証跡とする。
自動テストだけで段階3をGoにしない。

## 2. 役割と画面

| 役割 | 主な画面 | 必須確認 |
|---|---|---|
| 作業者 | 360px、390px、430px | ToDo、追熟実績、出荷、通信復旧 |
| 管理者 | 900px以上 | 工程ボード、詳細、期限、CSV、競合後の再読込 |
| 現場確認者 | 実際の端末・プリンター | 現物照合、A5ラベル、手書き復旧、操作時間 |
| 記録担当 | PC | SHA、環境、実施者、期待値、実測、残課題 |

PCは900px以上と文字200%でも横方向に情報を失わず、主要操作を完了できることを確認する。
作業者画面は各幅で横スクロールなしに主要操作を完了できることを確認する。

## 3. テストデータ

- 受注A 4.00kg、受注B 3.00kg、予備3.00kgの複合追熟計画。
- 同じ品種・等級の選果済みコンテナを複数用意し、一部だけを追熟へ割り当てる。
- 期限内、当日期限、期限超過、予定遅延の各状態を用意する。
- 出荷先はダミー名称・ダミー住所を使用し、実在顧客情報を使用しない。
- 表示IDと備考へ実施日を含む一意な識別子を付け、他の検証データと区別する。

## 4. 業務シナリオ

| ID | シナリオ | 合格基準 |
|---|---|---|
| S3-E2E-01 | 追熟計画から出荷 | 注入、抜き確認、寝かせ、追熟確認、出荷の実績時刻と担当者が記録され、現物工程と計画状態を別々に確認できる |
| S3-E2E-02 | 受注・予備・複合 | 受注A・Bと予備の内訳合計が追熟重量と一致し、工程ボードで用途を形と読み上げ名称で識別できる |
| S3-E2E-03 | 自動期限・遅延 | 期限内、当日、超過、確認遅延が仕様どおりに表示され、期限切れ対象を出荷確定できない |
| S3-E2E-04 | 部分出荷 | 4.00kgのうち1.50kg出荷後、同じコンテナIDへ2.50kgが残り、一覧・詳細・工程ボードで一致する |
| S3-E2E-05 | 出荷取消 | 出荷取消後に残量と在庫イベントが復元され、取消理由・担当者・時刻が履歴に残る |
| S3-E2E-06 | 予備振替 | 予備を受注へ振り替えても総重量が変わらず、対象受注と履歴が一致する |
| S3-E2E-07 | 工程ボード | 4列の件数・重量が表示項目と一致し、詳細パネルから既存の次工程入力を完了できる |
| S3-E2E-08 | 追熟ラベル | PDF・再印刷・手書き対応で表示ID、品種、等級、重量、工程情報が現物と一致する |
| S3-E2E-09 | CSV | 追熟・出荷・受注CSVの条件、件数、重量、状態、文字コードが画面と一致する |

## 5. 障害・権限・競合

| ID | 条件 | 合格基準 |
|---|---|---|
| S3-RES-01 | 各確定後に応答だけを失い再送 | 同じ冪等性キーで結果を再取得し、実績・出荷・履歴を重複作成しない |
| S3-RES-02 | 読み込み中に通信断・復旧 | 作業と無関係な情報を増やさず、理由と再試行操作を文字で表示する |
| S3-CON-01 | 2端末で同じ工程を確定 | 一方だけ成功し、他方は競合を表示して最新状態を再読込できる |
| S3-CON-02 | 2端末で残量を超える部分出荷 | 合計出荷量がシステム残量を超えず、失敗側に理由を表示する |
| S3-AUTH-01 | 未認証で業務URLを直接表示 | 業務データを表示せずログイン画面になる |
| S3-AUTH-02 | pending・disabled・権限不足 | 業務データと確定操作を許可せず、現在の利用状態を文字で説明する |

## 6. 性能

| ID | 条件 | 合格基準 |
|---|---|---|
| S3-PERF-01 | コンテナ20,000件 | 工程ボード初期表示、工程絞り込み、ID検索のp95が3秒以内 |
| S3-PERF-02 | 同時利用10セッション | エラー率1%未満、重量・状態・履歴の整合性違反0件 |
| S3-PERF-03 | 1コンテナへの部分出荷20件 | 詳細表示のp95が3秒以内、全履歴を無制限DOM表示しない |

p95は同じ条件を最低20回測定し、最初のウォームアップを除外する。
基準超過時は数値、利用影響、暫定回避策、責任者、期限を記録する。

## 7. 完了条件

- 全業務・障害・権限・競合シナリオがPass。
- 重量、状態、予定・実績、担当者、履歴が画面とDBで一致。
- P0/P1の未解決不具合が0件。
- 自動テスト、ローカル検証、CI、実機、複数端末、印刷、現場確認が完了。
- 対象SHA、環境、実施者、手順、期待値、実測、CIリンクを記録。
- フロント、バックエンド、DB・CI、現場・要件担当がGo/No-Goを判断。

発見した不具合や仕様変更はIssue #68へ混在させず、個別Issueとして再現手順と重大度を記録する。
