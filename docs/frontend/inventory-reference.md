# 在庫一覧・詳細・履歴画面

Issue #16（S1-07）のFlutter実装を定義する。在庫参照は読み取り専用とし、画面からSupabaseを直接呼ばず`InventoryRepository`を経由する。

## 画面フロー

1. 作業者はホームの「在庫参照」、管理者はサイドメニューの「在庫管理」から一覧を開く。
2. 在庫ID検索、状態フィルター、並び順を指定し、20件単位で表示する。
3. 一覧では在庫ID、品種・等級、現在量、予約量、利用可能量、状態、保管場所を確認する。
4. 作業者画面では詳細ページへ進み、管理画面では一覧右側に詳細を表示する。
5. 詳細から受入情報と選果情報を確認する。変更履歴は管理者だけが確認できる。

## データ取得

- 一覧は`containers`を基点に`varieties`、`grades`、`storage_locations`を取得する。
- 利用可能量は`current_weight_kg - reserved_weight_kg`で表示する。
- 検索は在庫表示IDに対してサーバー側で行い、状態・並び順・ページ範囲もData APIへ渡す。
- 詳細は`sorting_results`と`receiving_lots`を取得し、在庫の発生元を確認できるようにする。
- `user_roles`で管理者権限を確認できた場合だけ`change_history`を取得する。一般作業者は履歴APIを呼ばない。
- 一覧・詳細とも10秒でタイムアウトさせ、再試行可能な取得失敗と権限エラーを分けて表示する。

## 表示と操作

- 一覧行と詳細項目は罫線で区切り、カード、影、装飾用アイコンを使わない。
- 状態だけをピル型ラベルで示し、色と日本語の状態名を併用する。
- 矢印は「詳細」「前へ」「次へ」などの文字ラベルと併記する。一覧行のSemantics名には対象の在庫IDを含める。
- 360px、390px、430pxでは縦方向の一覧にし、画面全体の横スクロールを発生させない。
- 1280pxの管理画面では一覧と詳細を同時に表示し、一覧表に必要な場合だけ表内の横スクロールを許可する。
- 受入・選果の補足情報は8px角丸のモーダルで表示する。

## エラーと空状態

- 一覧・詳細の取得失敗は、再試行可能な場合だけ「再試行」を表示する。
- 認証切れと権限不足では再試行を表示せず、利用者が管理者または再ログインへ進める説明を出す。
- 条件に該当する在庫がない場合は、検索条件または状態の変更を案内する。
- 管理者に変更履歴がない場合と、一般作業者に閲覧権限がない場合を別の文言で表示する。

## 検証

- 利用可能量、重量表示、状態変換、権限エラー変換をUnit Testで確認する。
- ホーム導線、検索・フィルター・並び順、ページ移動、空、失敗、権限制御、詳細表示をWidget Testで確認する。
- 360px、390px、430pxで横方向のレイアウト崩れがないことを確認する。
- Canonical Ubuntu環境のGolden Testで390pxの一覧と1280pxの管理画面を確認する。

## UI変更レベル

W-09およびM-05とデザイン要件に定義済みの新規参照画面を実装する。既存業務の更新処理、データ構造、ナビゲーション体系、共通デザイン規則は変更しないため、追加のL2〜L4変更承認は不要と判断する。
