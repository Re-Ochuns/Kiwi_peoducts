# 収穫・仕入れ登録画面

Issue #13（S1-04）で、作業者ホームの「収穫・仕入れ登録」から受入登録と履歴付き修正を行う。

## 契約とデータ取得

- 登録は`receiving_register`、登録直後の修正は`receiving_correct`を使用する。
- 品種、農園、区画、樹体、仕入先、作業者はRLSで参照可能な有効マスターだけを取得する。
- 収穫では農園→区画→樹体の順に候補を絞り、品種は樹体から設定する。仕入れでは仕入先、仕入先管理ID、産地・区画、品種を入力する。
- 選果期限は個別契約どおりサーバーで計算し、完了結果に確定日を表示する。

## 二重送信と再送

- 確定処理中は戻る操作と確定操作を無効にする。
- 確認操作ごとにUUID v4の`idempotency_key`を生成する。
- 通信失敗など`retryable: true`の失敗は同じキーのまま最大2回自動再送し、`correlation_id`は試行ごとに生成する。
- 自動再送後も結果不明の場合、入力を変更しない手動再送では同じキーを使用する。入力または修正理由を変更した場合は新しいキーを生成する。

## エラー表示

- 項目が特定できる業務エラーは対象入力欄の近くへ表示する。
- 通信・サーバーエラーは確定操作の直前へ表示し、相関IDがある場合は問い合わせIDとして併記する。
- マスター取得失敗は画面全体のエラーとし、再試行操作を表示する。

## UI変更区分

既存要件で定義済みの画面と操作フローを実装するもので、要件変更はない。余白、文字、境界、入力配置はL1として扱い、角丸6px、通常コンテナの影なし、装飾アイコンなし、一つの作業段階につき主要確定操作一つを維持する。
