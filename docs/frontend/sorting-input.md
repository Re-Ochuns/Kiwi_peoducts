# 選果対象・選果入力画面

Issue #15（S1-06）のFlutter実装を定義する。更新処理の正本は
[`sorting_confirm`](../../contracts/rpc/sorting_confirm.md)であり、画面からSupabaseを直接呼ばず
`SortingRepository`を経由する。

## 画面フロー

1. 作業者ホームの「選果登録」から選果対象一覧を開く。
2. `awaiting_sorting`の受入ロットを期限、表示IDの順で表示し、ID・品種・産地で絞り込む。
3. 対象を選ぶと、元ロットID、元重量、品種、産地・区画を先頭に表示する。
4. 等級を選択し、その等級に属するコンテナの正味重量を0.01kg単位で入力する。
5. 選果後合計とロスを固定欄で確認し、確認モーダルから一括確定する。
6. 成功時は選果IDと生成されたコンテナIDを表示する。競合時は入力を破棄して最新一覧を再読込する。

## データ取得と更新

- 一覧はData APIから`receiving_lots.status = awaiting_sorting`を取得する。
- 選択肢は有効な`grades`と`workers`を取得する。
- 確定は`sorting_confirm`へUUID v4の`idempotency_key`と試行単位の`correlation_id`を付けて送る。
- 再試行可能な失敗だけを最大2回自動再送し、各試行を10秒でタイムアウトさせる。
- 同じ入力の手動再送では同じ冪等性キーを使い、入力変更後は新しいキーを発行する。
- `CONFLICT_STALE`では古い画面のまま再確定せず、対象一覧へ戻って再取得する。

## 入力と表示

- コンテナは1件以上、各重量は0より大きい0.01kg単位とする。
- 等級欄には等級ごとのコンテナ数と合計重量を常時表示し、入力欄は選択中の等級だけ表示する。
- 選果後合計が元重量を超えた場合は超過量を文字で示し、確認操作を無効にする。
- 重量入力済みのコンテナを削除する場合だけ確認する。
- 一覧行は角丸にせず、通常コンテナへ影を付けない。矢印は画面遷移だけに使用し、対象IDを含むSemantics名を付ける。
- 主要な確定操作は確認モーダル内の「選果を確定」一つとする。

## エラーと回復

- 読み込み失敗は一覧全体に再試行操作を表示する。
- 項目エラーは対象のコンテナ重量欄と確定操作付近に表示する。
- 通信失敗は同じ内容を再確認して送信でき、`correlation_id`があれば問い合わせ番号として表示する。
- 送信中は入力、追加、削除、確認を無効にして二重操作を防ぐ。
