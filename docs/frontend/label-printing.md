# ラベル確認・印刷・手書き対応画面

Issue #18（S1-09）のFlutter実装を定義する。PDF生成は`label-pdf` Edge Function、
状態更新は`label_mark_printed`、`label_reprint`、`label_mark_handwritten`を正本とし、
画面から直接呼ばず`LabelRepository`を経由する。

## 画面フロー

1. 作業者ホームの「ラベル発行」から対象一覧を開く。
2. 未対応・一部印刷と対応済みを切り替え、コンテナID、重量、品種、等級、産地、状態を確認する。
3. 対象を選び、A5ラベルの記載内容、必要枚数、印刷済み枚数、再印刷回数を確認する。
4. 担当者と枚数を指定してPDFを開き、ブラウザのPDF表示から印刷する。
5. 作業者が「印刷できた」を選んだ場合だけ印刷枚数を記録する。
6. 印刷できない場合は、同じ必須項目を確認モーダルで見ながら手書きし、対応を確定する。
7. 印刷済みラベルは理由を入力した場合だけ再印刷できる。

## 誤更新と重複の防止

- PDF生成・表示には状態変更の副作用を持たせない。
- PDF取得失敗、ポップアップ拒否、印刷中断では印刷済みRPCを呼ばない。
- ブラウザの印刷結果は自動判定できないため、利用者の明示的な確認後だけ状態を更新する。
- 状態更新はUUID v4の冪等性キーを付け、再試行可能な失敗だけ最大2回自動再送する。
- 同じ入力の手動再送は同じ冪等性キーを使い、担当者、枚数、理由、場所の変更後は新しいキーを発行する。
- 競合時は古い画面から再確定せず、一覧を再読込する。

## 入力と表示

- 印刷・再印刷の枚数は1〜999の整数とする。未対応時の既定値は残り必要枚数とする。
- 再印刷理由は必須で、入力値をそのまま履歴記録RPCへ渡す。
- 手書き確認にはコンテナID、産地・区画、品種、等級、正味重量、選果日、担当者を表示する。
- 冷蔵庫は契約どおり任意指定とし、有効な`cold_storage`だけを候補にする。
- 一覧行は角丸にせず、ラベルプレビューだけを罫線付きの意味あるコンテナとして扱う。
- 状態表示だけをピル型にし、影、装飾アイコン、装飾モーションは使用しない。
- 矢印は詳細遷移だけに使用し、読み上げ名には対象コンテナIDと「ラベル詳細を見る」を含める。

## エラーと回復

- 対象取得失敗とPDF取得失敗は同じ画面から再試行できる。
- PDFが開けない場合はポップアップ許可を確認する案内を表示し、状態は変更しない。
- 業務エラーと通信エラーは操作付近に表示し、`correlation_id`は問い合わせ番号として表示する。
- 処理中は戻る、入力、印刷、手書き対応を無効にして二重操作を防ぐ。

## 検証

- 未印刷、一部印刷、印刷済み、手書き済みの表示と操作可否をWidget Testで確認する。
- PDF取得失敗、PDF表示中断、再試行、明示確認後の状態更新を画面フローテストで確認する。
- 再印刷理由の必須検証と手書き必須項目の表示を確認する。
- 360px、390px、430pxで横方向のレイアウト崩れがないことを確認する。
- GoldenはUbuntu runnerで生成した基準画像を使用する。

## 実機確認

プリンター固有の余白、倍率、印字ずれは未確定のため、
[`A5ラベル印刷検証記録`](../printing/a5-label-verification.md)に従って対象プリンターとブラウザで確認する。
実機確認が終わるまで、印刷後の利用者確認は省略しない。

## UI変更レベル

W-05と既存デザイン要件に定義済みの画面を実装する。作業者ホームへ同格の作業入口を1件追加するが、
既存入口の順序・強さ・動作は変更しない。業務項目、状態遷移、共通デザイン体系の要件変更は行わないため、
追加のL2〜L4変更承認は不要と判断する。
