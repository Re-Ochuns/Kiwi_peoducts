# マスター管理画面

Issue #11（S1-02）のフロント実装。管理画面の「マスター」から、段階1で使用する9種類を一覧・検索し、権限を持つ管理者が登録、編集、無効化、再有効化できる。

## 対象

- 品種、等級、農園、区画、樹体、仕入先、作業者、保管場所、選果期限ルール
- 等級は固定8候補のため、新規登録とコード変更を行わず、表示順だけ編集する。
- 区画の農園、樹体の区画・品種、選果期限ルールの年度・月・品種は登録後に変更しない。

## 権限

- activeな利用者は一覧を参照できる。
- `profiles.role = administrator`かつactiveな利用者だけに、新規登録、編集、無効化、再有効化を表示する。
- 更新権限の最終判定はRPC側で行い、テーブルを直接更新しない。

## 画面と操作

- 種類、検索語、有効状態で一覧を絞り込む。無効データは初期表示から除外する。
- PCでは表を基本とし、十分な幅では一覧と右側詳細を同時に表示する。
- 登録・編集・状態変更は、それぞれ一つの主要確定ボタンを持つモーダルで行う。
- 更新と状態変更では理由を必須とし、重複、参照中、無効な親、版競合を日本語で表示する。
- 状態は色だけに依存せず「有効」「無効」を併記する。通常コンテナへ影を付けず、状態だけをピル型にする。

## RepositoryとRPC

- 一覧はRLSで保護された9テーブルをRepository経由で参照する。
- 更新は`master_register`、`master_update`、`master_deactivate`、`master_activate`だけを使用する。
- 更新要求はUUID v4の冪等性キーを持ち、再送可能な失敗だけ最大2回自動再送する。
- 更新後は全一覧を再取得し、`expected_version`の元になる最新版を表示する。

## 仕様変更レベル

`production-spec/06_SCREEN_REQUIREMENTS.md`と`08_DESIGN_REQUIREMENTS.md`で定義済みのマスター画面、管理ナビゲーション、モーダル、権限を実装する。新しい入力項目、確定手順、業務状態、共通デザイン体系は追加していないため、追加のL2〜L4変更には該当しない。
