# Architecture Decision Records

システム構成や複数担当領域へ影響する技術判断をADRとして記録する。

## 運用

- 状態は「承認待ち」「承認済み」「廃止」「置換済み」のいずれかとする。
- 承認済みADRの判断を直接書き換えず、変更理由を記載した新しいADRで置換する。
- ADRには対象Issue、関連要件、決定者、代替案、影響、未決事項の追跡先を含める。
- フロント、バックエンド、DB・CIの複数領域に影響するADRは3担当のレビューを必須とする。
