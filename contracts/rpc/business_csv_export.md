# 受注・追熟・出荷CSV（#66 / S3-09）

既存 `csv_export` の封筒、UTF-8 BOM、CRLF、全セル引用、数式対策、10,000行・10MiB上限、監査、タイムアウト、Web保存を共用する。
有効な認証利用者が参照可能。管理者の編集権限は要求しない。匿名・pending・無効ユーザーは拒否する。

filters は search（100文字以下、前後空白除去、大小文字を無視するリテラル部分一致）、status（既定all）、from_date/to_date（YYYY-MM-DD、両端を含む）を受け付ける。未知条件、不正日付・状態・逆転期間は拒否する。

| dataset | 行単位 | 状態 | 検索対象 | 日付対象・並び順 |
|---|---|---|---|---|
| orders | 受注 | all / active / draft / confirmed / in_progress / partially_shipped / shipped / cancelled | 受注番号・現在の顧客名・愛称 | 出荷予定日昇順、受注番号、ID |
| ripening | 追熟計画（未実施工程は空欄） | all / draft / confirmed / in_progress / completed / cancelled | 追熟ID・品種名・等級 | 注入予定日（JST）、注入予定日時昇順、追熟ID、ID |
| shipments | 出荷コンテナ明細 | all / confirmed / cancelled | 出荷ID・受注番号・出荷時顧客名/愛称・コンテナID | 出荷実績日（JST）、実績日時降順、出荷ID内部値降順、コンテナID、明細内部ID |

orders の active は一覧の「未出荷」と同じく draft/confirmed/in_progress/partially_shipped。
shipments は任意の order_id（UUID）で選択中の受注の履歴に絞れる。省略時は出荷一覧と同じ confirmed/in_progress/partially_shipped/shipped の受注に属する明細を対象とする。取消明細も含み、数量は元の出荷重量で状態により区別する。全体の重量合計を正味出荷量として扱わない。
収穫年度と追熟条件は計画保存値、工程実績は記録値を出力し、現行マスターで再計算しない。配送先・出荷時顧客も保存コピーを使用する。

正規化後の条件、認証出力者、生成日時、件数、バイト数、結果を既存の監査テーブルへ記録する。業務データは変更しない。
空件数はヘッダーのみ。出荷明細数を件数上限に使用し、上限超過では切り捨てファイルを返さない。

## 画面導線

- 受注一覧の「CSV出力」は、取得完了した一覧の検索・状態を引き継ぐ。検索欄の未適用文字列は含めない。顧客タブには表示しない。
- 追熟計画画面の「CSV出力」は全計画・実績を初期対象とし、検索・状態・注入予定日を指定できる。現在の計画画面は作成フォームで一覧条件を持たないため、未保存フォーム値を出力条件にしない。在庫の選択肢が空でも履歴を出力できる。
- 出荷予定・実績一覧の「CSV出力」は一覧対象の全受注の明細、選択受注の実績欄ではその受注の明細を初期対象とする。
- 確認ダイアログで条件を表示し、編集後に「CSVをダウンロード」で1回だけ要求する。出力中は変更・再送を無効化する。
- 読込中・読込失敗時は出力不可。空一覧でもヘッダーのみを出力可能。エラー表示・手動再試行・保存開始メッセージは既存CSVと共通。
- 業務更新なし。契約・UI導線の担当レビュー、Staging確認はPRで実施する。
