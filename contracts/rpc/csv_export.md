## 1. 概要とAPI

認証された利用者の検索条件に一致するデータを、一回の操作でCSVに出力する。
在庫・マスターの業務データは変更せず、出力記録だけを追加する。

- PostgreSQL Function `public.csv_export(req jsonb)` を使用する。
- CSV本体はJSON内の文字列として返し、FlutterがUTF-8バイト列にしてダウンロードする。
- PostgRESTの通常の行数上限1,000件による切り捨てを避けるため、単一のJSON応答とする。
- 読み取りに監査書き込みを伴うため、共通の更新RPCと異なる「監査付き読み取り契約」として承認を求める。
- 入力にSQL、テーブル名、任意列名は受け取らない。種別・ソート値は許可リストのみ。
- 認証情報はJWTから取得し、呼出側から出力者IDを指定できない。

## 2. 権限

| 出力 | 許可条件 |
|---|---|
| 在庫 | 有効なプロフィールを持つ認証済み利用者 |
| マスター | 同上。既存マスターのSELECT権限と一致 |
| 変更履歴 | 有効な管理者のみ |
| 監査記録の参照 | 有効な管理者のみ |

匿名、承認待ち、無効化済みユーザーを拒否する。
画面幅・管理画面の表示だけを権限判定に使わない。
既存RLSと同じ権限境界をサーバー側で検証し、将来RLSを細分化するときは本APIも同時に変更する。
監査テーブルへのクライアント直接INSERT/UPDATE/DELETEは許可しない。

## 3. 要求

```json
{
  "req": {
    "meta": {"correlation_id": "UUID v4"},
    "input": {
      "dataset": "inventory",
      "filters": {
        "search": "選果-2026",
        "status": "cold_storage",
        "sort": "updated_desc"
      }
    }
  }
}
```

| 項目 | 定義 |
|---|---|
| dataset | inventory / masters / history |
| meta.correlation_id | 呼出試行ごとのUUID v4。出力記録とエラーの追跡用 |
| filters | 対象別の許可フィールドのみ。未知フィールドは拒否 |
| 文字列 | 検索は前後空白を除去、最大100文字 |
| 日付 | YYYY-MM-DD。日時範囲はJSTの開始日以上、終了日の翌日未満 |
| 空条件 | 該当フィルターなし。NULLと空文字の正規化方法を実装・テストで統一 |

### 在庫条件

- `search`: 既存の在庫ID検索と同じILike部分一致。既存画面と同じく%・_をワイルドカードとして扱う。
- `status`: 既存在庫の8状態のいずれか。省略は全状態。
- `sort`: updated_desc / display_id_asc / current_weight_desc。
- ソートは既存在庫一覧と同じ第2キーを使い、必要なら内部IDを最終キーとして追加する。
- ページ番号は受け取らず、全ページの検索一致結果を対象にする。

### マスター条件

- `master_type`必須: variety / grade / orchard / orchard_plot / tree / supplier / worker / storage_location / sorting_deadline_rule。
- `search`: PR #45のMasterPageで適用済みの検索文字列。前後空白除去・小文字化後、MasterRecord.searchTextまたは関連マスター表示文字列へのリテラル部分一致とする。%・_は在庫検索と異なりワイルドカードにしない。
- 検索対象はPR #45のselectColumnsに含む値と、MasterPage._relatedTextで生成する親・品種等の表示文字列。選果期限ルールの年・月・日数・関連品種検索も保持し、検索を禁止しない。
- 実装時は検索対象列・関連表示文字列の組立てを画面とAPIで照合し、同じ条件で同じID集合になることをテストする。画面で取得済みの行だけをCSV化せず、サーバーで全一致行を抽出する。
- `active`: all / active / inactive。
- 並び順はPR #45に合わせ、等級は表示順、選果期限ルールは収穫年・収穫月・品種ID、その他はコード（仕入先は管理コード）順。同値時はIDを最終キーとする。

### 変更履歴条件

- `entity_type`: master / receiving_lot / sorting_result / container / label_job。省略は全種類。
- `entity_id`: UUID。省略は全対象。
- `from_date`、`to_date`: 任意。開始日が終了日を超えた場合は拒否。
- `changed_at DESC, id DESC`。
- 在庫詳細から呼ぶ場合はcontainerと選択中の内部IDを引き継ぐ。

## 4. CSV形式

- CSVはUTF-8 BOM付き。BOMはJSON応答全体ではなく、復号後の`data.csv`文字列先頭のU+FEFFを1個だけ指す。JSON本文の先頭にBOMを付けない。
- Flutterは`utf8.encode(data.csv)`で変換し、BOMを追加・除去しない。保存する最終バイト列の先頭3バイトは`EF BB BF`、直後はCSVヘッダー先頭であることを検証する。空件数でも同じとする。
- 改行CRLF、区切りカンマ、ヘッダー1行、空件数はヘッダーのみ。
- 全セルを二重引用符で囲み、内部の二重引用符は二重化。セル内改行を保持する。
- NULLは空セル、真偽値はtrue/false。識別子は文字列。
- 重量はkg、小数2桁、桁区切りなし、単位はヘッダーで示す。
- 日付はYYYY-MM-DD、日時はYYYY-MM-DDTHH:mm:ss.SSS+09:00（JST）。
- 列名・順序は以下で固定。既存列の意味・順序変更は契約改版の対象。

### 在庫

`在庫内部ID,在庫ID,品種,等級,元重量kg,現在重量kg,予約重量kg,利用可能重量kg,状態コード,保管場所コード,保管場所名,更新日時JST`

利用可能重量は現在重量から予約重量を差し引く。未設定の場所は空セル。
状態コードはDBと同じsnake_caseを出力する。

### マスター

種類ごとに以下の業務列を出力し、末尾に共通で
`有効,バージョン,更新日時JST`を付ける。

| 種類 | 業務列（順序固定） |
|---|---|
| variety | 内部ID,コード,品種名 |
| grade | 内部ID,等級コード,表示順 |
| orchard | 内部ID,コード,農園名 |
| orchard_plot | 内部ID,農園内部ID,コード,区画名 |
| tree | 内部ID,区画内部ID,品種内部ID,コード,樹体名 |
| supplier | 内部ID,管理コード,仕入先名 |
| worker | 内部ID,コード,作業者名 |
| storage_location | 内部ID,コード,保管場所名,場所種別 |
| sorting_deadline_rule | 内部ID,収穫年,収穫月,品種内部ID,期限日数 |

親参照は内部IDで保持する。今回のCSVはインポートAPIではない。
先頭ゼロや長い識別子を表計算ソフトで保持したい場合は、該当列を文字列としてインポートする。

### 変更履歴

`履歴ID,対象種別,対象内部ID,操作,変更前JSON,変更後JSON,理由,変更日時JST,変更者内部ID,変更者名,相関ID`

変更前後はJSON文字列として1セルずつ保持する。
マスターの個別列と異なり、履歴スナップショットの新規属性はJSON内にそのまま残す。

### CSVインジェクション

CSVの引用符によるエスケープとは別に、文字列セルの数式起動を防ぐ。

- 空白・制御文字・BOMを読み飛ばした最初の文字が = + - @ またはその全角表記の場合は、元の文字列全体の先頭にアポストロフィを付与する。
- TAB、CR、LFから始まる文字列も同様に無害化する。
- 値の切り捨てや、危険な文字だけを削除する方式は用いない。
- 数値列は検証済み数値を固定形式で出力する。
- 再保存したCSVを安全なまま再利用できる保証はしない。表計算ソフトによる再解釈を実機で確認する。

## 5. 応答とエラー

成功応答例:

```json
{
  "ok": true,
  "correlation_id": "UUID",
  "data": {
    "export_id": "UUID",
    "filename": "inventory_20260911T120000_01234567.csv",
    "row_count": 42,
    "csv": "\uFEFF\"在庫内部ID\",\"在庫ID\"\r\n",
    "generated_at": "2026-09-11T03:00:00.000Z"
  }
}
```

ファイル名はサーバーが種別・UTC日時・出力ID短縮値から生成し、検索条件を入れない。
失敗時は`ok:false,error:{code,message,retryable}`とcorrelation_idを返し、csvを返さない。

| code | 条件 |
|---|---|
| AUTH_REQUIRED | 認証なし・期限切れ |
| AUTH_FORBIDDEN | 無効・承認待ち・管理者限定対象 |
| VALIDATION_FAILED | 不正な種別、フィルター、日付、UUID |
| EXPORT_LIMIT_EXCEEDED | 行数またはバイト数の上限超過 |
| TIMEOUT | DBまたはクライアントでタイムアウト |
| NETWORK_FAILED | 応答を取得できない |

## 6. 上限・一貫性・再試行

- 暫定上限: 10,000データ行、CSVのUTF-8バイト数10MiB（BOM・ヘッダーを含む）。
- 上限+1行までで超過を検出し、先頭10,000行だけを成功として返さない。
- サイズ超過も全体を拒否する。絞り込みを案内する。
- DBは既存の8秒statement_timeout、Flutterは共通契約第7章と同じ10秒を上限とする。実装時に実際のPostgREST実効値も検証する。
- 抽出は単一のSQLスナップショットで行い、複数HTTPページの継ぎ合わせを避ける。
- 業務データの更新・排他ロックなし。出力完了まで業務入力を止めない。
- 再試行は新しい出力として現在のデータを取得する。過去CSVのキャッシュや永続保存はしない。
- 業務更新の冪等性キーは使わず、試行ごとに別のcorrelation_idと出力記録を残す。
- 二重クリックを画面で抑止。自動リトライはしない。

## 7. 監査

追加する専用テーブル`public.csv_export_audits`に以下を保存する案とする。

- export_id、correlation_id、認証ユーザーID、dataset
- 正規化した出力条件、生成日時、件数、UTF-8バイト数、結果コード
- 正常生成、上限超過、検証エラーの記録。業務データやCSV本体を監査へ複製しない。
- 匿名拒否、実行権限拒否、タイムアウト、トランザクションのロールバックは同一DBトランザクションの監査では保持できないため、基盤のAPI/DBログで追跡する。
- 成功監査は「サーバー生成完了」を意味し、ブラウザ保存完了を保証しない。
- 監査は追記専用、管理者参照のみ。自動削除は今回実装しない。
- 条件文字列にも業務情報が含まれ得るため、通常のアプリログに複製しない。

## 8. FlutterとUI変更判定

### 入口・条件・権限・確定操作

| 出力 | 入口 | 引き継ぐ適用済み条件 | 権限 | 確定操作 |
|---|---|---|---|---|
| 在庫 | 在庫一覧の「CSV出力」 | InventoryQueryの検索・状態・並び順。ページ番号は除外 | 有効な認証ユーザー | 対象・条件・全一致行が対象であることを確認し「CSVをダウンロード」 |
| マスター | PR #45のマスター一覧の「CSV出力」 | 選択中の種類、適用済み検索、有効/無効/全件。順序は種類別に固定 | 有効な認証ユーザー。編集権限canManageでは制限しない | 種類・条件を確認し「CSVをダウンロード」 |
| 変更履歴 | 在庫詳細の変更履歴欄の「履歴CSV出力」 | entity_type=container、選択中のentity_id | 有効な管理者のみ | 対象と期間を確認し「CSVをダウンロード」 |

- 3入口は同じ出力条件コンポーネントを使用し、入口に対応する種別を初期選択する。
  種別を切り替えた場合は前の種別のフィルターを送信せず、新しい種別の条件を明示して選び直す。
  管理者はここで変更履歴の対象種別・内部ID・期間を変更でき、省略は全対象を意味する旨を表示する。
- 在庫検索は検索実行後のInventoryQueryを引き継ぎ、未適用の入力文字列は含めない。
- PR #45のマスター検索は入力ごとに即時適用されるため、表示中の種類・検索・有効状態をスナップショットとして渡す。
  種類変更で検索欄が消去された場合は空検索を引き継ぐ。
- 条件画面で編集した場合は編集後の条件を表示し、確定時に送信内容を固定する。元一覧の条件は変更しない。
- 読み込み失敗時・権限確認中は出力を無効化する。空一覧はヘッダーのみをダウンロードできる。
- 一般利用者には変更履歴の入口・種別選択を表示しない。権限変更や直接API呼び出しはサーバーで再検証する。
- 出力中は条件変更と再確定を無効化し、通信エラー後は明示操作だけで再試行する。
- 「CSVをダウンロード」で1回のAPI呼び出しを行い、成功後に保存を開始する。
  成功表示はブラウザへの保存開始を示し、端末への保存完了を保証しない。
- 読込中・空件数・成功・権限拒否・上限超過・通信エラーを区別する。
- Webダウンロードは一時Blob URLを使い、保存操作後に解放する。
- 360/390/430pxとPCで確認する。
- UI判定: 既存の在庫・マスター一覧および在庫詳細への出力操作追加と条件画面はL2相当として承認を求める。
  共通ナビゲーション項目の追加は行わない。必要になった場合はL3として別途影響確認する。
- マスター一覧はPR #45を利用し、新設しない。独立した全変更履歴一覧の新設は対象外。
- 正本の画面要件第7章と同じ導線・範囲を本PRでレビューする。承認は未取得のまま明記する。
