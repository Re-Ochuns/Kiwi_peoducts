# 01. 本番用業務要件書

## 1. 目的

収穫・仕入れから選果、冷蔵在庫、追熟、出荷までの重量と所在を一貫して管理し、作業者が次に行う作業、管理者が今後準備すべき在庫・追熟・出荷予定を確認できるようにする。

## 2. 利用者

| 利用者 | 主端末 | 主な業務 |
|---|---|---|
| 作業者 | スマートフォン | 収穫・仕入れ、選果、追熟計画作成、ラベル対応、エチレン注入、抜き確認、追熟確認、出荷実績 |
| 管理者 | PC | 工程ボード、マスター、顧客・受注、追熟計画、在庫予約、予定確認、履歴付き修正 |

両者は権限上の役割ではなく、利用画面を区別する呼称とする。メニューから作業画面と管理画面を切り替えられる。
追熟計画は管理画面だけでなく、作業者向けスマートフォン画面からも作成できる。

## 3. 基本業務フロー

```text
収穫・仕入れ
→ 選果待ち（冷蔵）
→ 選果
→ 等級別コンテナ生成
→ ラベル印刷／手書き対応
→ 冷蔵在庫
→ 追熟計画・部分予約
→ エチレン処理
→ 寝かせ
→ 追熟確認
→ 出荷可能
→ 出荷・在庫減算
```

### 3.1 工程ボード

- 管理者向けPC画面に、コンテナの現在工程を俯瞰する工程ボードを設ける。
- 工程ボードは選果済み、追熟、寝かせ、出荷可能の4列で構成する。
- 各列に該当するコンテナを表示し、工程別のコンテナ数と重量合計を確認できるようにする。
- 各コンテナでは表示ID、品種、サイズ、重量、工程別の期限・予定日時を確認できるようにする。
- コンテナを選択すると詳細と次工程の操作を開き、ボードを離れずに確認・入力できるようにする。
- 工程変更はドラッグだけでは確定せず、工程ごとの必須情報を入力し、確認操作を経て確定する。
- 工程ボードは現物工程の可視化を目的とし、追熟計画状態、在庫予約状態、要確認フラグを1つの状態へ統合しない。

## 4. 収穫・仕入れ

### 4.1 共通

- 共通名称は「収穫・仕入れ」とする。
- 収穫日と仕入れの入荷日は同一の日付項目で扱う。
- 受入ロット単位で総重量とコンテナ数を登録する。
- 選果前はコンテナ個別ID・個別重量を管理しない。
- 登録後は「選果待ち」とし、冷蔵する。
- 選果期限はマスターから計算し、初期値は30日とする。

### 4.2 自園収穫

- 日付、産地・区画、樹体名、品種、選果期限、総重量、コンテナ数、担当者を登録する。
- 異なる樹体は同一受入ロットへ混在させない。

### 4.3 仕入れ

- 日付、仕入先、仕入先管理ID、産地・区画、品種、選果期限、総重量、コンテナ数、担当者を登録する。
- 樹体名は持たず、画面上は「仕入れ」と表示する。
- 仕入先はマスターから選択する。詳細項目は未決事項とする。

## 5. 選果

- 一つの受入ロットを一度にすべて選果する。途中状態はシステム管理しない。
- 等級は `5L、4L、3L、LL、L、M、S、SS` とする。
- 等級ごとに「＋」操作で出力コンテナを追加する。
- 各コンテナには風袋を除いた正味重量を0.01kg単位で入力する。
- 等級重量は所属コンテナ重量の合計から自動計算する。
- 選果後重量は全出力コンテナの合計から自動計算する。
- `ロス = 元ロット総重量 − 選果後重量` とする。
- 選果後重量が元ロット総重量を超える場合は確定できない。
- ロス率警告は初期実装せず、現場確認事項とする。
- 元の物理コンテナを再利用しても、選果後コンテナには新しいIDを発行する。
- 選果確定後、元ロットを閉じる。

## 6. ラベル

- 選果後および追熟開始時にコンテナラベルを作成する。
- 初期本番はA5 PDFを生成し、ブラウザから印刷する。
- 印刷状態は、未印刷、一部印刷、印刷済み、手書き対応済みとする。
- 印刷済みまたは手書き対応済みになるまで工程を確定できない。
- 手書き対応は作業者が「手書き対応」ボタンを押した時点で完了とする。
- 再印刷を許可し、再印刷履歴を残す。

## 7. 顧客・受注

- 顧客と配送先を分離し、一顧客へ複数配送先を登録できる。
- 受注には顧客、配送先、注文日、出荷予定日、品種、等級、注文量kgを持つ。
- 受注状態は、下書き、確定、進行中、一部出荷、出荷済み、キャンセルとする。
- 追熟開始時に受注を進行中へ変更する。
- 作業開始前のキャンセルは在庫予約を解除する。
- 作業開始後のキャンセル量は予備へ振り替える。
- 受注変更で追熟計画または予約に不整合が出る場合、計画確定を解除して要再確認にする。

## 8. 追熟計画・予約

- 作業者画面と管理者画面の両方から追熟計画を作成できる。
- 使用する冷蔵在庫、追熟重量、追熟場所、エチレン注入予定日時、担当者を登録する。
- 追熟重量に対して複数の内訳を登録し、各内訳へ受注または予備と割当重量を指定する。
- 受注内訳では対象受注を指定し、予備内訳では受注を指定しない。
- 冷蔵在庫を選択した際は、品種、等級、使用可能量を表示する。
- マスターから取得したエチレン処理条件、寝かせ条件、追熟完了予定日時を登録前に表示する。
- 注文または予備作成を契機に追熟ロットを作る。
- 一つの追熟ロットへ複数受注と予備を割り当てられる。
- 追熟ロットと受注の間に割当データを持つ。
- 内訳から用途区分を自動判定し、受注のみを「受注」、予備のみを「予備」、両方を含む場合を「複合」とする。
- 内訳合計が追熟重量と一致しない場合、追熟計画を確定できない。
- 冷蔵コンテナ内の重量を部分予約する。
- `使用可能量 = 現在量 − 予約量` とする。
- 作業開始前は予約を変更・解除できる。
- 作業開始後は予約解除できない。
- 計画変更で不整合が生じた場合、計画を未確定へ戻す。
- 計画割当と追熟後割当は原則変更しない。
- 予備量は管理者が在庫状況を見て手入力する。
- 予備は後から受注へ振り替えられる。

## 9. 追熟作業

- 年度・収穫月・品種に一致する追熟マスターを計画作成時にコピーする。
- S2のエチレン処理時間は既定1週間（168時間）とし、注入予定から抜き確認予定を計算する。確定時の処理時間を保存し、既定値の変更で確定済み計画を変えない。年度・品種別の自動計算はS3で拡張する。
- 計画作成後にマスターが変わっても既存計画を自動更新しない。
- エチレン注入、エチレン抜き確認、追熟確認は作業者または管理者が手動で完了する。
- 実績日時はボタン押下時刻を初期値とし、手動変更できる。
- 予定値と実績値を分離する。
- 追熟場所は場所マスターから選択する。
- 初期本番では寝かせ延長、再エチレン処理、追熟失敗処理を扱わない。

## 10. 出荷

- 出荷日、受注番号、出荷重量、使用追熟コンテナ、取引先を記録する。
- 一受注へ複数の出荷実績を登録できる。
- 出荷確定時に対象コンテナの重量を減らす。
- 一部出荷後も同じコンテナIDで残量を保持する。
- 他の予約がなければ残量を予備へ変更する。
- システム残量を超える出荷は登録できない。
- 出荷取消は在庫を戻す逆処理として履歴に残す。

## 11. 期限

| 期限 | 動作 |
|---|---|
| 選果期限 | 要確認。自動期限切れにしない |
| 冷蔵在庫期限 | 要確認。管理者判断 |
| エチレン注入予定 | 遅延警告 |
| エチレン抜き予定 | 確認タスクを期限超過にする |
| 追熟確認予定 | 確認タスクを期限超過にする |
| 賞味期限 | エチレン注入実績日時から計算し、自動で出荷不可にする |
| 出荷予定日 | 出荷遅延警告 |

期限切れ在庫に予約・受注・計画が関連する場合、それらを要再確認にする。現物廃棄は別操作とする。

## 12. 修正・履歴

- 次工程開始前は管理画面から修正できる。
- 修正前後の値を履歴へ保存する。
- 各履歴は対象の受注、在庫、追熟計画の詳細画面で表示する。
- 次工程開始後に元データの誤りが判明した場合の訂正方法は未解決事項とする。
