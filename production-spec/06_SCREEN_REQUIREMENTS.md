# 06. 画面一覧・画面要件

画面ごとの構成を本書で定義し、共通の視覚・操作基準は [08_DESIGN_REQUIREMENTS.md](08_DESIGN_REQUIREMENTS.md) に従う。

## 1. 共通ナビゲーション

- スマホでは作業画面、PCでは管理画面を初期表示する。
- メニューからいつでも画面モードを切り替えられる。
- 手動選択は端末内に保存し、次回は前回選択を優先する。
- 画面遷移する項目には右向き矢印を表示する。
- 説明文や装飾アイコンを増やさず、項目名、値、状態、期限、エラーを優先する。
- 作業者向けスマートフォン画面には固定の下部タブを設けない。
- 作業者ホームに主要工程の作業ボタンを縦一列で表示し、各工程の入口を集約する。
- 工程画面から作業者ホームへ戻る操作は画面上部に表示する。

## 2. 作業者向けスマホ画面

| ID | 画面 | 主な表示・操作 |
|---|---|---|
| W-01 | ToDo | 期限超過、今日、今後の作業。該当作業へ直接遷移 |
| W-02 | 収穫・仕入れ登録 | 区分、日付、産地、樹体または仕入先、品種、総重量、コンテナ数、担当者 |
| W-03 | 選果対象 | 選果待ちロット、期限、総重量 |
| W-04 | 選果入力 | 等級ごとのコンテナ追加、各正味重量、合計、ロス |
| W-05 | ラベル対応 | PDF、印刷状態、再印刷、手書き対応 |
| W-06 | 追熟計画作成 | 冷蔵在庫、追熟重量、受注・予備の内訳、場所、注入予定、マスター条件、完了予定、担当者 |
| W-07 | 追熟作業 | 対象ID、品種、等級、重量、場所、予定値、実績値、完了 |
| W-08 | 出荷作業 | 受注、取引先、コンテナ、出荷重量、残量、確定 |
| W-09 | 在庫参照 | ID検索、状態、現在量、予約量、使用可能量、場所 |

### 作業者ホームUI

- 「収穫・仕入れ登録」「選果登録」「追熟計画作成」を同じ強さの縦一列の作業ボタンとして表示する。
- 固定の下部タブは表示しない。
- 期限超過、今日、今後の順で作業を表示する。
- 作業一覧では時刻、作業名、対象ID、品種、等級、重量、場所を読み取りやすい順序で表示する。

### 追熟計画作成UI

- 追熟重量に対して複数の内訳行を登録できるようにする。
- 内訳行では割当種別を受注または予備から選択し、受注の場合は受注番号と割当重量、予備の場合は割当重量を入力する。
- 同じ追熟コンテナへ、複数受注、受注と予備、または予備のみを割り当てられる。
- 内訳行を追加・削除でき、内訳合計と未割当重量を入力中に常時表示する。
- 各内訳重量が0以下、または内訳合計が追熟重量と一致しない場合は確認・確定操作を禁止する。
- 選択した在庫の品種、等級、使用可能量を入力欄付近に表示する。
- 追熟場所とエチレン注入予定日時を入力する。
- マスターから取得したエチレン処理条件、寝かせ条件、追熟完了予定日時を一連の流れとして表示する。
- 確認後に追熟計画IDを発行する。

### 選果入力UI

```text
M
コンテナ1  [10.25] kg
コンテナ2  [ 9.80] kg
[＋ コンテナを追加]
M合計       20.05 kg
```

- コンテナ追加は大きなタップ領域とする。
- 削除時は、入力済み重量がある場合だけ確認する。
- 等級選択欄では、各等級のコンテナ数と等級重量を表示する。
- 選択中の等級に属するコンテナだけを入力領域へ表示する。
- 元ロットID、元重量、品種、産地・区画は画面上部に表示する。
- 画面下部の固定領域には選果後合計、ロス、確認操作だけをコンパクトに表示する。
- ラベル印刷・手書き対応・最終確定は確認モーダルへ分離する。

### 作業実績UI

- 予定日時・温度を初期値として表示する。
- 完了ボタン押下時に現在日時を実績値へ入れる。
- 必要な場合だけ日時、温度、担当者、備考を変更する。

## 3. 管理者向けPC画面

### 3.1 ホーム

1. 期限超過・要確認、在庫・予約不足、Googleカレンダー同期失敗をまとめた優先確認一覧
2. 今日の作業
3. 今後7日の追熟・出荷予定
4. 今日の作業、要確認、7日以内の予定、予約不足の件数集計

件数集計はすべて対応する一覧へ遷移できる操作要素とし、押せそうに見える非操作カードを作らない。

### 3.2 主要メニュー

| メニュー | 初期表示 |
|---|---|
| ホーム | 対応が必要な情報のみ |
| 工程ボード | 選果済み、追熟、寝かせ、出荷可能のコンテナ。ID、品種、サイズ、重量、期限・予定日時、用途区分 |
| 受注 | 入力前に確認する受注用在庫と既存受注一覧。利用可能量・選択コンテナから受注入力へ遷移 |
| 追熟計画 | 進行中と今後7日。ID、予定、品種、等級、重量、場所、状態 |
| 在庫管理 | 使用可能在庫。ID、品種、等級、現在量、予約量、使用可能量、状態 |
| 出荷 | 今日と今後7日。受注番号、取引先、予定日、重量、状態 |
| マスター | 品種、等級、場所、作業者、仕入先、期限、追熟条件 |

終了済み、期限切れ、キャンセルはフィルター操作後に表示する。

### 3.3 工程ボード

- 選果済み、追熟、寝かせ、出荷可能を横並びのカンバン列で表示する。
- 各コンテナカードには、表示ID、品種、サイズ、重量を表示する。
- 選果済みには保管期限、追熟と寝かせには終了予定日時、出荷可能には出荷日時を表示する。
- コンテナカードを選択すると右側の詳細パネルを開き、工程情報と次工程の入力画面を表示する。
- 工程変更はドラッグ操作では確定せず、詳細パネルで必要事項を入力し、確認画面を経て確定する。
- カード左上の状態アイコンは1つだけ表示し、色で工程、形で追熟用途を示す。
- 用途の形は、予備を中空円 `○`、受注を点 `●`、受注と予備の複合を円と点 `⊙` とする。
- 用途区分が未確定の選果済みカードは、アイコンの色だけを工程識別に使用する。
- 工程名は各列見出しへ文字で表示し、用途形状はボード上部の凡例でも確認できるようにする。

### 3.4 受注前の在庫選択

受注入力前に、品種・等級・現在量・予約済み量・利用可能量・産地・選果日を確認する。同一品種・等級のコンテナを選び、「この在庫で受注登録」へ進む。受注確定時に初めて予約する。画面状態と遷移の詳細は[受注時予約への変更](11_ORDER_INVENTORY_RESERVATION.md)に従う。

## 4. 詳細画面

- 受注詳細：受注内容、配送先スナップショット、予約対象・重量・未計画分・計画引き継ぎ済み分、追熟割当、出荷、変更履歴。
- 追熟計画詳細：計画値、実績値、割当、予約、場所、タスク、変更履歴。
- 在庫詳細：親ロット、表示ID、重量、予約、使用可能量、状態、場所、工程履歴。
- 出荷詳細：出荷明細、使用コンテナ、重量、取消履歴。

## 5. ラベル

### 選果後

- コンテナ表示ID、産地・区画、品種、等級、正味重量、選果日、担当者。

### 追熟

- コンテナ表示ID、産地・区画、品種、等級、正味重量、エチレン注入日時、抜き予定、出荷可能予定、場所、内訳。

ID、品種、等級、重量、エチレン注入日時を優先して大きく表示する。

## 6. デザイン・操作

- スマホ幅360〜430pxで横スクロールを発生させない。
- タップ領域44px以上、主要ボタン56px以上とする。
- 通常作業ボタンは同じ強さで表示し、特定工程だけを色で強調しない。
- IDは等幅フォント、選択対象IDは16px以上、主要重量は24px以上とする。
- 要確認は黄、期限切れ・エラーは赤、確定操作は濃い緑とする。
- 色だけで状態を伝えず、必ず状態名・警告文を併記する。
- モーダルはタイトル、主要値、操作だけを表示する。
- 反復する業務情報はカードを並べず、一覧または表で表示する。
- ID、重量、期限、次の操作の順に視覚的な優先順位を付ける。
- 補助情報へ薄い文字色を使用する場合も、屋外のスマートフォン操作で判読できるコントラストを確保する。
- 一画面へ全工程の情報を並べず、現在の作業に必要な入力と確認情報だけを表示する。

## 7. CSV出力

段階1（Issue #19）では、在庫・マスター・変更履歴の3種類を対象とし、現在の検索・絞り込み結果をCSV出力できるようにする。
マスターはIssue #11（PR #45）の9種類を対象とする。受注・追熟計画・出荷・顧客のCSVは後続段階で実装し、段階1に含めない。

| 対象 | 入口と引き継ぐ条件 | 権限・確定操作 |
|---|---|---|
| 在庫 | 在庫一覧から、適用済み検索・状態・並び順を引き継ぐ。ページ番号は除外 | 有効ユーザーが条件を確認し「CSVをダウンロード」 |
| マスター | マスター一覧から、適用済み種類・検索・有効状態を引き継ぐ | 有効ユーザーが条件を確認し「CSVをダウンロード」。編集権限では制限しない |
| 変更履歴 | 在庫詳細の変更履歴欄から、対象種別containerと選択中の内部IDを引き継ぐ | 有効な管理者が対象・期間を確認し「CSVをダウンロード」 |

各入口は共通の出力条件画面を使う。種別変更時は以前の条件を解除し、新しい対象の条件を確認する。
管理者は変更履歴の対象種別・内部ID・期間を変更できる。一般利用者には変更履歴の選択肢を表示しない。
在庫の未適用検索入力は出力に含めず、マスターの即時適用検索は表示中の値を使う。
出力対象は取得済みの表示行だけでなく全ページの一致結果とし、権限・上限をサーバーで再検証する。
独立した全変更履歴一覧や共通ナビゲーション項目は今回追加しない。

詳細な列・文字コード・安全対策・監査・上限は[CSV出力契約案](../contracts/rpc/csv_export.md)に定義する。
この段階1の具体化とL2相当の導線はPR #44で承認を求めるもので、承認前に実装済み・確定済みとは扱わない。


### S3-09 受注・追熟・出荷CSV

受注一覧、追熟計画画面、出荷予定・実績一覧と選択受注の実績欄にCSV出力を設ける。
受注の適用済み検索・状態、出荷実績の選択受注を引き継ぎ、出力前に検索・状態・期間を確認できる。
追熟は計画と3工程の実績を1計画1行、出荷は取消を含むコンテナ明細1行とする。
権限、列順、期間の意味、上限、監査、保存形式は[CSV拡張契約](../contracts/rpc/business_csv_export.md)に従う。
