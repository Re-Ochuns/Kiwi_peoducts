# 04. 段階別リリース計画

## 共通方針

- 各段階を現場検証してから次へ進む。
- データ構造は段階3までを見据えて設計する。
- 未解決事項は推測で実装しない。
- 試作版ではダミーデータのみ使用する。

## 段階1：受入・選果・在庫・ラベル

### 対象

- 収穫・仕入れロット登録
- 選果待ち
- 選果一括登録
- 等級別コンテナと個別実測重量
- ロス自動計算
- 表示ID発行
- A5ラベルPDF、再印刷、手書き対応
- 冷蔵在庫一覧・詳細
- 品種、等級、圃場・区画・樹体、仕入先、作業者、選果期限マスター
- 作業画面と管理画面
- 次工程前の履歴付き修正
- CSV出力

### 受け入れ条件

- 受入ロット総重量とコンテナ数を登録できる。
- 仕入れ時に樹体入力を要求しない。
- 選果後の全コンテナへ正味重量と一意な表示IDを登録できる。
- 重量超過時に選果を確定できない。
- ラベル対応完了前に冷蔵在庫へ確定できない。
- スマホとPCから同じ在庫を参照できる。

## 段階2：受注・追熟計画・予約・ToDo

### 対象

- 顧客・複数配送先
- 受注登録・状態管理
- 追熟ロット、受注・予備割当
- コンテナ重量の部分予約
- 予約不足・在庫不足表示
- 作業タスク
- スマホToDo、PC予定画面
- 作業者向けスマートフォン画面からの追熟計画作成
- Googleカレンダー一方向同期
- 同期失敗の再試行・警告
- 追熟・選果期限マスター拡張

### 受け入れ条件

- 使用可能量から二重予約できない。
- 受注変更時に計画と予約を要再確認にできる。
- 作業開始前キャンセルで予約が解除される。
- カレンダーから該当作業画面を開ける。
- 同期失敗でも計画データが失われない。
- 作業者画面から用途、受注、冷蔵在庫、追熟重量、場所、注入予定を指定して追熟計画を作成できる。

## 段階3：追熟実績・出荷・期限

### 対象

- エチレン注入、抜き確認、寝かせ、追熟確認
- 予定値と実績値
- 追熟場所
- 予備振替
- 部分出荷、在庫減算、出荷取消
- 自動期限切れと関連データの要再確認
- 出荷・追熟・受注CSV

### 受け入れ条件

- 作業完了時刻を自動入力し、必要なら修正できる。
- 現物工程と追熟計画状態を独立して確認できる。
- 部分出荷後の残量が同じコンテナIDへ残る。
- システム残量を超える出荷を確定できない。
- 賞味期限到来時に対象を出荷不可へ変更できる。

## リリース判定

各段階で、代表的な収穫ロットと仕入ロットを使用して現場リハーサルを行う。作業時間、入力ミス、紙との二重管理、ラベル可読性、重量整合性を確認し、重大な未解決事項が残る場合は次段階へ進まない。
