# 工程ボードからの受注・追熟計画登録（Issue #118）

## 操作

管理者の「在庫」タブで出荷予定日・品種・等級・注文量（kg、小数2桁）を入力し、「候補を表示」で工程別の候補に絞る。検索解除で通常の在庫へ戻る。検索・選択では予約しない。

候補を選ぶと4条件、対象ID、使用量、利用可能量と登録後残量、追熟予定を引き継ぐ。顧客と、その顧客に属する有効な配送先を選び、確認画面から一度で確定する。完了時に受注・計画番号を示し、ボードを再取得する。

## 選択と数量

ユーザー合意済み：1コンテナ／1ロットで注文量を満たす方式。未追熟は注文量だけを新規計画に使用する。既存の予備ロットは計画を増やさず受注を紐付ける。複数候補の合算は対象外。

- 冷蔵コンテナ：利用可能量 = 現在重量 − 既存予約量。注文量と同量の計画、受注割当、計画所有の予約を作る。物理重量を減らさない。
- 確定済み予備計画：物理的確保量には有効な計画予約量を用いる。
- 開始済み／完了済みロット：物理的確保量には工程内コンテナの現在重量合計を用いる。
- ロット候補量 = min(明示的な予備割当量, max(0, 物理的確保量 − 未出荷の受注割当量))。出荷済み重量を受注割当から差し引く。同一ロットは1候補で、コンテナへの按分はしない。
- 既存ロットへの登録は、注文量だけ予備割当を減らし、新規受注割当へ移す。計画・予約・実行状態・予定を保持し、必要な作業タスクを再投影する。

## 日程・入力の初期仕様

以下は初期実装の前提であり、ユーザーによる明示的な承認済み事項とは区別する。

- 出荷予定日の **09:00（Asia/Tokyo）** を基準とし、余裕時間は追加しない。
- 未追熟は品種・仕入月に対応する有効な追熟マスターの注入時間と寝かせ日数から逆算する。開始が現在より前になる候補、マスターがない候補は除外する。
- 既存ロットは完了予定 <= 出荷時刻 < 出荷可能期限・賞味期限の両方。期限不明の出荷可能コンテナ、期限切れ・要確認のロットは除外する。
- 新規計画の保管場所と担当作業者は登録画面で選ぶ。場所は候補の現在地を初期値とする。既存計画の場所・担当者は保持する。
- 顧客と配送先は既存マスターから選択する。この画面での新規マスター作成は含めない。

## 確定と復帰

受注登録・受注確定・計画登録／予備移管・計画確定・予約・割当・監査履歴は単一トランザクション。失敗は全てロールバックする。既存計画／出荷操作と同じ排他ロックを取り、確定時に状態・数量・日程・候補バージョンを再検証する。

通信結果が不明な場合は入力変更や離脱を止め、同じ冪等キーで再送する。競合は条件を再検索し、顧客・配送先などの入力を保持して再選択できる。送信中はタブ切替・画面離脱・多重送信を止める。

一般の確定済み割当を直接変更する制約は維持する。予備移管は本RPC内部のトランザクション・ロット・新規受注に限定した権限でのみ許可する。

## 既存仕様との関係

受注一覧・追熟計画・CSVは既存のorders、ripening_lots、ripening_allocations、inventory_reservationsを参照するため、別管理の数量を追加しない。変更・取消・部分出荷は既存RPCの制約と予約解除を利用する。実作業の開始・物理移動はこの確定では行わない。

#109 の独立した受注予約フローは変更・完了扱いにしない。本機能では既存の計画所有予約を使い、同じ数量への受注所有予約を重ねない。
