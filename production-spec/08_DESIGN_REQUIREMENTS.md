# 08. デザイン要件書

## 1. 目的

農園の作業者と管理者が、説明を読み込まずに対象、数量、状態、期限、次の操作を判断できる業務画面を設計する。見栄えのための装飾より、作業速度、誤操作防止、屋外での可読性を優先する。

## 2. 対象画面

| 画面モード | 主端末 | 主な用途 |
|---|---|---|
| 作業者画面 | スマートフォン縦向き | 収穫・仕入れ、選果、追熟計画、追熟作業、出荷作業 |
| 管理画面 | PC | 受注、追熟計画、在庫、出荷、マスター、予定・警告確認 |

画面モードは権限の違いではなく、端末と作業内容に合わせた表示の違いとする。

## 3. 基本原則

1. 一画面では一つの作業を完了させる。
2. 現在の作業に不要な情報を表示しない。
3. 表示優先順位は、対象ID、重量、期限・状態、次の操作、補助情報の順とする。
4. 説明文を常設せず、業務上必要な名称、値、警告だけを表示する。
5. 装飾目的のアイコン、写真、イラストを使用しない。
6. 画面遷移には右向き矢印、前画面へ戻る操作には左向き矢印を表示する。
7. アイコンだけで意味を伝えず、列見出し、凡例、文字ラベルまたはアクセシブルな名称で意味を確認できるようにする。
8. 同じ形のカードを並べすぎず、反復情報は一覧または表で表示する。
9. 色だけで状態を伝えず、状態名または警告文を併記する。
10. 押せそうに見える要素は操作可能にし、操作できない情報欄と外観を区別する。

## 4. 情報の視覚的優先順位

### 4.1 最優先情報

- 対象の表示ID
- 現在入力・処理する重量
- 期限超過、在庫不足、予約不足、入力エラー
- 工程を確定する主要操作

### 4.2 通常情報

- 品種、等級
- 現在状態
- 予定日時、実績日時
- 追熟場所
- 担当者

### 4.3 補助情報

- 圃場・区画
- 親ロット
- 更新日時
- 変更履歴へのリンク

補助情報を薄い文字色にする場合も、屋外のスマートフォン画面で判読できるコントラストを確保する。

## 5. 用語と表示文

- 工程名称は「追熟」に統一し、旧称の「成熟」は使用しない。
- 農園名は「おおくま農園」と表示する。
- 作業名称は動作が分かる表現とする。例：`収穫・仕入れ登録`、`選果登録`、`追熟計画作成`。
- ボタンは結果が分かる表現とする。例：`選果を確定`、`確認して寝かせを開始`、`出荷を記録`。
- 「こちらを入力してください」など、項目名から推測できる説明は表示しない。
- PoCで実処理を行わない機能は、必要な箇所だけに「疑似動作」と表示する。

## 6. 作業者向けスマートフォン画面

### 6.1 共通構成

- 対象幅は360〜430pxの縦向きを優先する。
- 横スクロールを発生させない。
- 固定の下部タブは設けない。
- ホームに主要工程の作業ボタンを縦一列で表示する。
- 工程画面では、画面上部にホームへ戻る操作を表示する。
- 工程入力中は他工程へのナビゲーションを表示しない。
- 主要作業ボタンは同じ視覚的強さにし、特定工程だけを色で優先しない。

### 6.2 作業者ホーム

表示順序は次のとおりとする。

1. 日付と「今日の作業」
2. `収穫・仕入れ登録`、`選果登録`、`追熟計画作成`
3. 期限超過
4. 今日の作業
5. 今後の作業

作業一覧では、時刻、作業名、対象ID、品種、等級、重量、場所を表示する。狭い一行へ連結せず、意味のまとまりごとに改行または列を分ける。

### 6.3 入力画面

- 入力項目は縦一列を基本とする。
- 関連する短い数値項目だけ、横二列を許可する。
- ラベルは入力欄の上に表示する。
- 入力欄の高さは48px以上とする。
- 日時は初期値を設定し、手動変更できる。
- 完了操作はフォーム末尾に幅いっぱいで表示する。
- 入力、確認、登録完了の順で進め、確認・完了はモーダルで表示する。

### 6.4 選果画面

- 画面上部に受入ロットID、元ロット重量、品種、圃場・区画を表示する。
- 等級選択欄に各等級のコンテナ数と等級重量を表示する。
- 選択中の等級だけ、コンテナIDと実測重量入力欄を表示する。
- コンテナ追加操作は、対象等級名を含む48px以上のボタンとする。
- 選果後合計とロスは常時確認できるようにする。
- 画面下部に固定する領域は、高さを抑え、選果後合計、ロス、確認操作だけを表示する。
- 元重量やラベル操作を固定領域へ重複表示しない。
- ラベル印刷、手書き対応、最終確定は確認モーダルへ分離する。
- 元重量を超えた場合は赤いエラー文を表示し、確認・確定操作を禁止する。

### 6.5 追熟計画作成画面

- 使用する冷蔵在庫、追熟重量、追熟場所、エチレン注入予定、担当者を入力する。
- 追熟内訳は行形式とし、1つの追熟コンテナへ受注と予備を同時に登録できるようにする。
- 内訳行では受注または予備、受注番号、割当重量を入力し、必要に応じて行を追加・削除できるようにする。
- 内訳合計と未割当重量を入力領域の近くに常時表示する。
- 内訳合計が追熟重量と一致しない場合は確認操作を無効にする。
- 在庫選択後、品種、等級、使用可能量を入力欄の近くに表示する。
- エチレン処理、寝かせ、追熟完了予定を左から右への工程として表示する。
- 登録完了モーダルでは追熟計画IDと主要予定日時を表示する。

## 7. 管理者向けPC画面

### 7.1 共通構成

- 左側に主要メニューを常設する。
- メニューはホーム、受注、追熟計画、在庫管理、出荷、マスターとする。
- 一覧と詳細を同時に確認する必要がある画面は、一覧＋右側詳細の構成を使用する。
- 多項目データはカードではなく表を基本とする。
- ID列と重量列は視線で追えるように配置と桁を揃える。

### 7.2 管理ホーム

- 最上部に今日の作業、要確認、7日以内の予定、予約不足の件数を表示する。
- 件数欄はすべて対応する一覧へ遷移できる操作要素とする。
- 主領域では、次の順で優先確認一覧を表示する。
  1. 期限超過
  2. 在庫不足・予約不足
  3. Googleカレンダー同期失敗
- 優先確認一覧には状態名、概要、対象ID・重量、遷移先を表示する。
- 今日の作業は時刻順に表示する。
- 今後7日の追熟・出荷予定は日ごとの簡潔な一覧とする。

### 7.3 一覧・表

- 見出し行とデータ行の境界を明確にする。
- 数値列は右揃え、IDと文字列は左揃えとする。
- 重量は小数点以下2桁と単位kgを表示する。
- 不足量やエラー値は赤、注意は黄、確定・出荷可能は緑で表示する。
- 行全体が詳細へ遷移する場合は、ホバー・フォーカス状態と右向き矢印を表示する。
- 終了済み、期限切れ、キャンセルは初期表示から除外し、絞り込み後に表示する。

### 7.4 工程ボード

- GitHub Projectsのような高密度の横並びカンバンを基調とする。
- 各列は選果済み、追熟、寝かせ、出荷可能とし、列見出しにコンテナ数と重量合計を表示する。
- カード上段は状態アイコン、表示ID、サイズを同じ高さに配置する。
- カード本文には品種と重量を表示し、工程に応じて保管期限、終了予定日時または出荷日時を表示する。
- カード左上の状態アイコンは1つに統合し、工程と用途を別々の記号として並べない。
- アイコンの色は工程を表す。選果済みはグレー、追熟はアンバー、寝かせは紫、出荷可能は緑とする。
- 追熟用途は同じアイコンの形で表す。予備は中空円 `○`、受注は点 `●`、複合は円の中央に点を置く `⊙` とする。
- 色と形の意味をボード上部の簡潔な凡例で示す。
- 工程は列名でも確認できるため色だけに依存せず、用途記号にはアクセシブルな名称を設定する。
- カード選択時は右側に詳細パネルを表示し、ボード上の位置を保ったまま内容を確認できるようにする。

## 8. 文字

| 用途 | 最小サイズ・方針 |
|---|---|
| ページタイトル | 28px以上、太字 |
| 主要重量 | 24px以上、太字、桁を揃える |
| 選択対象ID | 16px以上、太字 |
| 本文・入力値 | 16px以上 |
| ラベル・状態 | 14px以上 |
| 補助情報 | 12〜13px。重要情報には使用しない |

- IDと重量は可能な限り改行しない。
- 日本語の作業名称が不自然な位置で改行されない幅を確保する。
- 数値には等幅数字を使用し、重量一覧の小数点位置を揃える。
- 文字だけを過度に太くせず、サイズ、余白、配置も使って階層を作る。

## 9. 色と境界

| 用途 | 色 |
|---|---|
| 背景 | 白または明るい無彩色 |
| 基本文字 | 黒に近い濃色 |
| 主要操作・選択状態 | 濃い緑 |
| 注意・要確認 | 黄・アンバー |
| 期限切れ・エラー・不足 | 赤 |
| 進行中 | 青系 |

- 通常情報の境界線は背景と識別できる濃さにする。
- 淡い背景色だけで状態を区別しない。
- 濃い緑の面を多用せず、主要操作または重要な識別情報に限定する。
- 装飾的なグラデーションや影を使用しない。固定操作領域やモーダルの前後関係に必要な最小限の影だけ許可する。

## 10. 操作領域と余白

- 通常のタップ・クリック領域は44px以上とする。
- スマートフォンの主要確定ボタンは54〜56px以上とする。
- 隣接する操作同士に8px以上の間隔を確保する。
- 一覧行は情報量に応じて64〜106pxを目安とし、文字を詰め込まない。
- スマートフォンでは左右16pxを基本余白とする。
- PCでは一覧密度を優先し、カードごとに大きな余白を設けない。

## 11. 状態・エラー・完了

- エラーは対象入力欄の近くと確定操作付近に表示する。
- エラー発生時は該当操作を無効化し、理由を文字で表示する。
- 無効ボタンは、操作できないことが視覚的に分かる状態にする。
- 工程の状態と要確認フラグを別に表示する。
- 登録完了モーダルには、結果、発行ID、次回予定、閉じる操作だけを表示する。
- 破棄や取消などの不可逆または復旧に手間がかかる操作には確認ダイアログを表示する。

## 12. レスポンシブ要件

- 360px、390px、430px幅で主要作業を確認する。
- PC管理画面は1280px以上を基準とし、最低900pxまで利用可能にする。
- 管理画面を狭い画面で開いた場合は、表の内容を無理にカード化しない。
- 横スクロールが必要な管理表は表領域内だけに限定する。
- 固定ヘッダーや固定操作欄が入力対象を覆わないことを確認する。
- 200%文字拡大時も主要操作と値が欠けないことを確認する。

## 13. アクセシビリティ

- 入力欄には対応する文字ラベルを関連付ける。
- キーボードフォーカスを視認できるようにする。
- 色覚に依存せず、状態名と警告文を文字で表示する。
- 装飾アイコンは使用しない。画面遷移を示す矢印と、工程ボードの状態・用途を識別する機能アイコンだけを使用する。
- 工程ボードの状態アイコンには判別可能なアクセシブル名称を設定し、工程名と用途凡例を文字でも表示する。
- モーダル表示時は背後の操作へフォーカスが移動しないようにする。
- ブラウザ標準の文字拡大、入力支援を妨げない。

## 14. 使用しない表現

- TOPページや工程画面の説明文・紹介文
- 装飾目的のアイコン、写真、イラスト
- すべての情報を個別の角丸カードへ入れる構成
- スマートフォンの固定下部タブ
- アイコンだけの工程ボタン
- 操作できないがボタンのように見える件数カード
- 重要な期限、ID、重量への12px以下の文字
- 一つの長い文字列へID、品種、等級、重量、場所を連結する表示
- 選果画面の入力欄を覆う大きな固定集計パネル

## 15. デザイン受け入れ基準

- 作業者ホームから3回以内の操作で、収穫・仕入れ、選果、追熟計画作成の入力を開始できる。
- 390px幅で主要画面にページ全体の横スクロールが発生しない。
- 選果入力中に選択等級、コンテナID、入力重量、選果後合計、ロスを同時に確認できる。
- 選果画面の固定領域がコンテナ入力欄を継続的に覆わない。
- 管理ホームを開いた時点で、最優先の要確認項目と次の操作が分かる。
- 主要な一覧でID、重量、状態、期限を視線移動だけで比較できる。
- 工程ボードで選果済み、追熟、寝かせ、出荷可能の位置と、受注・予備・複合の用途を一覧のまま識別できる。
- 工程ボードのカード左上に、工程色と用途形状を統合したアイコンが1つだけ表示される。
- 画面内の主要操作が、文字ラベルなしのアイコンだけになっていない。
- 固定下部タブが作業者画面に表示されない。
- 「成熟」という旧称が画面に表示されない。
